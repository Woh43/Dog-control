## 启动预对位与 RViz

旧版 IOSDK 构造函数中的小力矩预对位曾在移植时遗漏，本次恢复为独立、非阻塞的单次辅助。桌面入口启用后，控制器状态保持 PASSIVE，硬件只有在 12 个电机反馈有效、控制器完整接管且写入心跳持续有效时才自动开始，力矩方向保持旧版转子侧约定：

| 阶段 | 时长 | 输出侧力矩幅值 |
| --- | --- | --- |
| hip/thigh 预对位 | 300 ms | hip 0.95 N·m、thigh 0.63 N·m，calf 为零 |
| 三关节预对位 | 300 ms | hip 0.95 N·m、thigh 0.63 N·m、calf 1.52 N·m |
| 释放 | 300 ms | mode0，位置、速度、力矩与增益全零 |

该动作会在 START 标定之前发送非零力矩；只有辅助窗口之外的未标定/被动输出才维持 mode0，不能再把所有 PASSIVE 情况都表述为恒定零输出。过程中通信/CRC 失败、软件急停、写入心跳过期、撤销控制器接管或标定复位会中止并退零；中止后不自动重试，需要重启恢复。任一电机反馈不完整或陈旧时不满足开始条件。

若启用辅助，须等约 0.9 秒流程完成后，再新按 START 记录零点；辅助期间提前按下或持续按住 START 不会在完成时自动采零。START 完成后仍回到 PASSIVE，LT+A 才请求起身。预对位提供旧版对位动作，不证明已达到准确机械参考姿态或关节正方向已验收。

**本次通信探针仅发送 mode0 全零命令，真实非零预对位仍未验收。恢复后的构建、16 个 CTest 套件及包含 RViz 的 11 组完整启动 PTY 检查已通过。** 测试中的 1,800 个预对位 FOC 包均符合旧版固定力矩；实际带力矩辅助和承重运动仍未验收。模拟电机使用独立大核上的单事件循环，42 次可恢复 PTY IO 失败已保留记录，不将软件测试表述为硬实时达标。详见 [兼容验收记录](compatibility-validation-20261103.md)。

## 方向、输出和模型

电机配置顺序固定为 FR、FL、RR、RL，每腿 hip、thigh、calf。方向映射按旧驱动与当前 URDF 坐标推导，并通过 launch 参数开放。零输出通信只能确认协议反馈，不能物理确认关节正方向；正式标定与带力矩动作前仍需核对安装方向。

真机与 Fortress 从同一 `controllers.yaml` 读取主循环 250 Hz、NMPC 20 Hz、求解线程 2，以及起身/WBC 增益、步态和速度限制；`real_controller.yaml` 只覆盖时钟、硬件/启动等差异。主循环预算 4 ms、NMPC 周期 50 ms 均为目标值，尚不能视为完整活动模式实测达标。公共低速限制为前后/侧向各 0.05 m/s、偏航 0.2 rad/s。

当前安装版本的仿真与最新 `real.launch` PTY 实际参数已重新对照：并集 73 项中 64 项相同，其余涉及 `use_sim_time`、`hardware_mode`、`simulation_passive_hold`、`joint_limit_tolerance_rad`、四项 `/clock` QoS 与 `robot_description`。描述差异包含 IO 插件、仿真传感器、初始姿态和碰撞配置；惯性、视觉和运动学关节一致。两路使用同一控制器库、规范 URDF 和 NMPC task/reference；controller_manager 均为 250 Hz，29 份共享文件指纹一致。真机参数来自完整启动 PTY，不代表实物承重运动通过。参数差异与指纹见 [兼容验收记录](compatibility-validation-20261103.md)。

`run_real.sh` 在 RK3588 上默认选择可用的大核，本机为 CPU 4–7；`DOG_CPU_AFFINITY=none` 关闭，或设置显式 CPU 列表覆盖。这只影响本次进程及子进程，没有修改全局调度器、CPU governor 或实时权限。离线并行 NMPC/WBC 测试显示大核绑定能减少超周期，但仍有调度长尾，不能宣称硬实时达标。

运行入口默认设置 `OPENBLAS_NUM_THREADS=1`、`OMP_NUM_THREADS=2`，可用 `DOG_OPENBLAS_NUM_THREADS`、`DOG_OMP_NUM_THREADS` 明确覆盖。历史大核离线测试曾收到 120 份新策略，NMPC 平均 30.89 ms、最大 47.40 ms；1,486 次 WBC 全部有效，P99 2.31 ms、最大 4.84 ms，3 个计算周期超过 4 ms，且未计入电机串口。该记录为 `log/basic-motion-20261102/runtime-final.json`，不代表本轮完整控制周期已达标。

此前部署检查发现 SDK 的 `sendRecv(MotorCmd*)` 会把接收超时改回 20 ms，因此采用原始字节接口和 `BlockYN::NO`，保留实际 2 ms 超时并校验反馈。当时健康三腿并行通信平均约 0.69 ms、P99 约 1.15 ms；含右前失联时一轮约 6.5 ms，不满足 4 ms 周期。这些是历史测时；本轮仍需按当前版本核对。软件陈旧命令保护只能阻止恢复调度后重发旧命令，不能在主机完全停顿时替代电机端看门狗或物理急停。

当前向电机发送 `q_des、dq_des、tau_ff、Kp、Kd` 五分量，由电机侧计算 PD。公共起身/落稳 Kp 为 45→55 N·m/rad、Kd 为 1.5→2.5 N·m·s/rad；WBC 外层关节跟踪 Kp 为髋 50、腿 20，Kd=2。真机与当前 Fortress 使用相同数值，本轮关闭真值辅助的低速完整动作与 60 秒站立回归已通过。历史 250 Hz 主机 PD 纯力矩实验的失败、候选通过与剩余问题见 [当时的链路检查](real-control-validation-20261102.md)，不能直接当作恢复电机侧 PD 后的当前结论。

发送前检查当前反馈与五分量的有限性和增益范围，计算 `abs(tau_ff)+Kp*abs(q_des-q)+Kd*abs(dq_des-dq)`；若超过关节 effort 限值，则对该关节 `tau_ff、Kp、Kd` 用同一比例缩放，保留目标位置/速度。这给出当前采样时的贡献上界，不能保证两个主机采样之间的连续实际力矩上限，也没有验收真实电机力矩标定。

Fortress 的当前电机模型每 1 ms 物理步用实时物理关节反馈计算 PD，外环命令经过一周期与物理步相位延迟；仿真与真机共用 NMPC/WBC 算法及控制配置。该模型是理想电机侧伺服，不能据此声明真实伺服带宽、时延或连续力矩饱和已测得。

历史静力平衡检查中，15.15 kg 模型在原起身/落稳参数下的固定四足平衡、摩擦锥和力矩限制通过，所需最大关节力矩约 6.78 N·m。它不证明当前展开过程或动态稳定。

规范模型总质量 **15.15 kg**，躯干质量 7.85084 kg。补入 base 原点 1.30084 kg 电池，质心和平行轴惯量同步；电池尺寸未知，自身惯量仍为点质量近似。详见 [电池模型记录](battery-model-validation-20261102.md)。
